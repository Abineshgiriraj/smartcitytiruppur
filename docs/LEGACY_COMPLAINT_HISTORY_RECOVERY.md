# Historical complaint recovery: local pilot

The first release separates original employee activity from operational assignments. Do not change complaints.assigned_officer_id, status, deadlines, assignment history, escalation history or login accounts. Contact matches and lifecycle actions are candidates; neither alone authorizes access. Do not publish raw dumps, contact values, actual approval CSVs or citizen records in Git.

1. Back up the database and use an isolated local copy containing the raw tables and current users/officers. Keep the live escalation worker and main unchanged.
2. Run `php tools/import_verified_legacy_history.php` (read-only coverage by employee/action).
3. An authorized municipal administrator must verify source identity, current login ID and officer ID using official personnel records, and verify what original action 0/1 means and whether those events are authorized historical visibility. Verify a sample against the old officer report. A shared phone/email/name or numeric ID alone is insufficient. Review conflicts separately; do not approve unresolved identities. Only approve an employee/action pair if ALL events in that pair may be shown as historical metadata. Do not infer assignments or resolution.
4. Prepare a private CSV with header:
   `legacy_user_id,officer_id,login_user_id,action_code,evidence_reference`
   Each row is a separate reviewed employee/action approval. Evidence is a non-sensitive official review reference. Never commit the filled CSV. The current login ID is users.id, not officers.id.
5. Preview: `php tools/import_verified_legacy_history.php --approved-csv=PATH --admin-user-id=ID`
   No writes. Verify totals and ownership samples. CLI admin ID records the responsible reviewer; the operator must already be authorized to use the local database. It does not authenticate the reviewer.
6. Apply the additive SQL migration manually ONLY to the isolated test copy. Apply the approved CSV there with `php tools/import_verified_legacy_history.php --approved-csv=PATH --admin-user-id=ID --apply --confirm-db=TEST_DATABASE_NAME`. The DB name check prevents accidental target mismatch, not proof of local environment. Use separate local credentials and inspect the connection before apply. No automatic production migrations.
7. Login as an approved officer. Dashboard has a separate historical/lifetime card; My Complaints links to the read-only history page. Admin report links to a separate historical report (not for Department Heads, to preserve scope). Existing current reports remain unchanged. Historical history lists reference, category, department, registration date, status and last approved event; no citizen contacts, attachments, full complaint details or update privileges. Full details require separately verified authorization.
8. Compare counts against the original officer report. Check two different officer sessions, unapproved officer, revoked approval, inactive/relinked account, deleted complaints, repeated source events and current/history overlap. Repeat the same import to verify zero new events. Verify a conflicting CSV rolls back. Verify existing complaint counts, status and ownership are unchanged.
9. Revoke access by setting revoked_at on the corresponding approval using an authorized DB administrator; the reporting queries immediately exclude it. Reapproval/reassignment requires separate review, not an automatic overwrite. Do not change officer login identities without reviewing approvals.
10. No deployment until local MariaDB integration and original report comparisons pass. This branch is a pilot, not a completed migration. The missing source lifecycle and unresolved identity cases require a separate review. Current assignment/worker reference filters are separate issues and intentionally untouched.

The new reports count DISTINCT complaint relationships per officer; cross-officer totals may overlap. An original employee can have many actions for one complaint. The source lifecycle ID is unique in the recovered table, and no existing operational assignment rows are imported or fabricated.
